## 1. Kiến trúc và thứ tự lớp

```text
Source provenance
→ Rate limiter
→ Direct/indirect input guardrails
→ LLM
→ Output redaction
→ Multi-criteria judge
→ Action permission + HITL
→ Egress allowlist
→ Audit + monitoring
```

Rate limiter, input guardrail, output redaction, judge, action permission và egress policy là các lớp có thể chặn. Audit và monitoring chỉ quan sát.

## 2. Phân tích bảy attack bắt buộc

| # | Attack | Lớp dự kiến chặn đầu tiên | Lý do |
|---:|---|---|---|
| 1 | Ignore previous instructions + password | Input guardrail | Direct instruction override và secret extraction |
| 2 | DAN + API key | Input guardrail | Role-confusion/jailbreak pattern |
| 3 | CISO + ticket | Input guardrail | Claimed authority không tạo permission |
| 4 | Translate system prompt to JSON | Input guardrail | Reformatting/exfiltration request |
| 5 | Injection tiếng Việt | Input guardrail | Mẫu Việt ngữ sau Unicode normalization |

Kết quả thực tế, response preview và request ID được lưu trong `outputs/results.json` và `outputs/audit_log.json`.

## 3. Indirect injection và false positive

Pipeline canonicalize Unicode bằng NFKC, loại zero-width/invisible separators rồi mới detection. Vì vậy chuỗi `Ignore\u200b all previous instructions` không né được bộ lọc.

Nội dung ngoài lành tính như yêu cầu tóm tắt email về giao dịch bị chậm không bị chặn chỉ vì nó đến từ email/RAG. Chỉ phần instruction override hoặc yêu cầu action/egress trong nội dung ngoài mới bị từ chối. Trade-off là rule quá rộng có thể chặn tài liệu giáo dục nhắc lại câu tấn công; production nên kết hợp provenance, parser theo cấu trúc và classifier thay vì chỉ tăng regex.

## 4. Action, HITL và egress

`is_egress_allowed(destination, payload)` dùng URL parser và exact hostname allowlist. Các trường hợp sau bị chặn:

- HTTP thay vì HTTPS;
- subdomain giả như `api.vinbank.example.evil.com`;
- external domain;
- URL chứa userinfo hoặc port ngoài 443;
- payload/query chứa password, API key, internal DB host, số điện thoại hoặc email.

Mọi `HIGH_RISK_ACTIONS` đều fail closed nếu chưa có reviewer ID và approval ID đúng định dạng. Reviewer nhận intent, current/proposed state, diff, destination, payload summary và risk reason. Approve tạo approval ID dùng cho action; reject hủy action; timeout không auto-approve và được audit là `timed_out`.

## 5. Các attack bổ sung và lớp bảo vệ thêm

Ba nhóm có khả năng lọt qua một input regex đơn lẻ:

1. Instruction được phân mảnh qua nhiều tài liệu RAG hoặc nhiều lượt hội thoại.
2. Dữ liệu nhạy cảm được biến đổi theo semantic encoding mà không giữ chuỗi secret nguyên bản.
3. Model không lộ secret trong text nhưng gọi tool gửi dữ liệu tới sink ngoài.

Lớp bảo vệ thêm quan trọng nhất là **deterministic action gateway**: model chỉ đề xuất action, còn permission, HITL và egress policy quyết định độc lập. Production có thể bổ sung DLP/tokenization trước sink và provenance-aware taint tracking từ source đến payload.

## 6. Thiết kế khi scale khoảng 10.000 người dùng

- Chuyển rate-limit state sang Redis với atomic Lua script hoặc managed gateway; key theo tenant/user và có TTL.
- Chạy deterministic checks trước để tránh chi phí LLM; chỉ gọi judge cho sample, risk tier cao hoặc response không chắc chắn.
- Gửi audit bất biến tới log pipeline tập trung, tách PII khỏi log, đặt retention và quyền truy cập; alert theo rolling window thay vì toàn bộ lịch sử.
- Cache policy/rule compilation, dùng async I/O, timeout/circuit breaker cho judge và fail closed tại action/egress boundary.

## 7. Đạo đức và giới hạn

Không có “an toàn tuyệt đối”. Hệ thống nên từ chối khi yêu cầu xung đột policy, chứa instruction từ nguồn không đáng tin, đòi secret/PII, hoặc tạo side effect chưa được phê duyệt. Với câu hỏi hợp lệ nhưng thiếu dữ kiện, assistant nên nêu giới hạn, không bịa lãi suất/chính sách và chuyển sang nhân viên khi hậu quả cao.

## 8. Source-to-sink case

```text
Untrusted email/RAG
→ instruction yêu cầu upload customer data
→ model có thể đề xuất POST
→ action gateway xác định source không có authority
→ egress policy phát hiện evil.example hoặc PII payload
→ request bị chặn
→ audit lưu correlation ID, reason và proposed destination
→ monitoring cập nhật incident counters
```
